# Per-guest physical key rule editor

The Key mappings page keeps a draft for one guest identity at a time. Presets and custom modifier bindings remain the lower-precedence layer. Up to 32 saved `keyRules` can override that layer. Each enabled rule has one to four physical HID source usages, one to four emitted usages, a priority from -100 to 100, and an enabled flag. Left and right modifier usages are distinct. A matching exact chord wins over single-key rules; higher priority breaks ties within a layer. A destination is emitted once and is never mapped again.

The source and guest columns expose physical HID usages. The chord recorder uses browser `KeyboardEvent.code` for common keys and captures the keys pressed before the first release; users can adjust sided modifiers in the selector. This browser hint is checked again by the native profile validator. The editor blocks duplicate enabled triggers at the same priority, invalid or repeated keys, and every trigger containing both physical Ctrl keys. The latter chord is reserved for emergency return before mapping. Disabled rules stay saved but do not emit input. Existing host-local profiles without `keyRules` deserialize with an empty list.

The local tester computes an eight-byte boot keyboard report from the draft and a captured physical chord. **Clear / all up** resets the displayed source and report. It does not send or log keystrokes. Recording is enabled only while the actor reports confirmed local control; switching and guest routes disable it. There is no live send-test control because this build has no explicit ready-guest test API with guaranteed all-up cleanup. Applying a draft uses the existing saved-profile and pending native installation path; the mapping engine defers an active edit until physical keys are all up.

Verification: `cargo test -p esp32-kvm-desktop --no-default-features`, `cargo fmt --all -- --check`, `node --experimental-strip-types --test apps/desktop/src/*.test.mjs`, TypeScript `tsc --noEmit`, and the Vite production build. Native capture timing and the actual keyboard remain physical gates; no COM port or guest test is involved.
