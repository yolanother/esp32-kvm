# Retained bond inventory and offline removal

Minor-two firmware answers `GET_BONDS` with at most eight distinct, nonzero opaque 16-byte tokens. The payload is format version 1, count, then exactly count tokens. This is separate from STATUS, which still reports only live slots. The firmware reads the persisted pairing table on NimBLE's host loop through the existing 20 ms single-slot RPC and returns BUSY/NACK if the read fails. Neither BLE peer addresses nor bond keys cross into USB frames.

`HostActor::refresh_bond_inventory` accepts only the response matching its outstanding sequence, verified session, and route generation. `SetupSnapshot.retained_bonds` is `None` when unread, unsupported, expired, or faulted; `Some(vec![])` means a fresh authoritative empty inventory. The snapshot also carries the host monotonic observation time. The actor invalidates the snapshot after one second of driven time, and every explicit refresh starts from unknown until a matching response arrives.

Offline deletion works while the route and pairing state are local. The actor requests a fresh pre-inventory and returns `AlreadyAbsent` if it excludes the token. If present, it sends FORGET_BOND, requires the exact ACK, then requests another fresh inventory and succeeds only when the token is absent. A wrong ACK, stale BONDS frame, NACK, timeout, or unplug cannot remove the local mapping profile. SetupService keeps its own profile until the actor returns confirmed success; an `AlreadyAbsent` result with a local profile needs deliberate reconciliation and is not silently treated as success.

Tauri's `BackendSnapshot` and `SetupSnapshot` expose `retainedBondTokens` independently from live `bondTokens`; absent inventory is `None`, while a fresh empty list is `Some([])`. The setup service explicitly refreshes inventory before deletion, requires verified local state and token presence, then calls the serialized actor worker. The worker publishes the actor's post-delete snapshot before replying, and the service requires fresh exclusion before removing a local profile. It can remove a firmware bond even if no local profile exists. Ordinary setup commands retain a 500 ms deadline; inventory refresh has 900 ms and forget has 2500 ms to cover the actor's bounded pre-read, ACK retry, and post-read without a routine late-success UI timeout. The actor still fails closed on its own shorter wire deadlines.

The NimBLE peer store and the application token table are separate stores. `hid_guest_pairing_forget` deletes the peer record, then commits the revised token table. ESP-IDF 5.5.1 NimBLE's `ble_store_util_delete_all` treats a missing record as success, so retrying after a token-table commit failure can repeat peer deletion. The portable mock test forces one commit failure and confirms that the in-memory token remains visible and a retry succeeds. This is recoverable retry behavior, not an atomic transaction across both stores or proof about power loss at every storage boundary. A live BLE/power-cycle gate remains pending.

Verification: `cargo test -p esp32-kvm-protocol`, `cargo test -p esp32-kvm-host-actor --test actor`, and the MSVC scripts under `firmware/tests/{pairing,hid,integration}`. Full ESP-IDF build and physical BLE removal are integration gates. This work does not access COM7.
