# ESP32 KVM USB protocol v1 schema

This is the normative payload schema for major version 1, minors 0, 1, and 2. `docs/spec/04-usb-protocol.md` defines behavior. Every integer is unsigned unless signed below. All fixed integers are little endian. Frame header and CRC are outside these payloads. The message kind constants are maintained in `crates/protocol/src/lib.rs`; `generate-header.ps1` regenerates `protocol_v1.h` from them. A host sends HELLO minor 0 to read CAPS, then sends HELLO at the highest mutually supported minor before SESSION_OPEN. Minor 0 remains routing compatible but does not expose or accept pairing control.

## Envelope

`magic:u16=0x4b56, major:u8=1, kind:u8, payload_len:u16=0..512, flags:u16=0, session:u64, seq:u32, route_generation:u32, payload, crc32c:u32`. Maximum decoded frame is 540 bytes. COBS encoding has a trailing zero delimiter. HELLO uses session zero. CAPS supplies a random nonzero session. All later host commands echo it. Session and route generation checks are stateful and precede input effects.

## Fixed payloads

| Kind | Payload in wire order | Constraints |
|---|---|---|
| HELLO 01 | `minor:u16, features:u32` | Major is in header; unknown required feature bits reject negotiation. |
| HEARTBEAT 10 | `host_tick:u64` | Monotonic within session. |
| GET_STATUS 11 | empty | |
| SWITCH 20 | `slot:u8, expected_generation:u32, new_generation:u32` | Slot 0 local; 1..max_connections guest. New generation must differ from expected. Retries repeat session and seq exactly. |
| RELEASE_ALL 21 | empty | Accepted in valid session even while disarmed. |
| ARM 22 | `slot:u8, generation:u32` | READY slot and all-up baseline required. |
| KEY_STATE 30 | `modifiers:u8, reserved:u8=0, usages:[u8;6]` | USB keyboard usage IDs; six zeroes means release. |
| POINTER 31 | `buttons:u8, dx:i16, dy:i16, wheel:i8, pan:i8` | Signed values; preserve totals by splitting, never wrapping. |
| CONSUMER_STATE 32 | `usage:u16` | Zero releases. |
| PAIR_BEGIN 40 | `duration_seconds:u16` | 1..60 in the schema; current firmware supports 60. Requires negotiated minor 1, local disarmed route. |
| PAIR_CANCEL 41 | empty | |
| GET_BONDS 44 | `format_version:u8=1` | Negotiated minor 2 only. Request a fresh retained-bond snapshot. |
| BONDS 45 | `format_version:u8=1, count:u8=0..8, tokens:[u8;16]×count` | Exactly `2+16×count` bytes. Tokens must be nonzero and distinct. Response echoes the GET_BONDS session, sequence, and current route generation. An empty successful response is authoritative; failed reads produce NACK, never an empty BONDS response. |
| DEVICE_SELECT_REQUEST 50 | `slot:u8, request_id:u32` | Board request only; host arbitrates. |
| UPDATE_PREPARE 60 | empty | Releases and suspends. |
| ACK/NACK 70/71 | `original_kind:u8, original_seq:u32, error:u8, resulting_generation:u32` | ACK error 0. NACK: 1 VERSION, 2 NOT_READY, 3 STALE_SESSION, 4 STALE_ROUTE, 5 PAUSED, 6 BAD_PAYLOAD, 7 BUSY, 8 UNSUPPORTED. |
| INPUT_PROGRESS 72 | `accepted_seq:u32, ble_enqueued_seq:u32` | Neither denotes guest consumption. |

## Canonical CBOR payloads

Each variable payload is one definite-length CBOR map with unsigned integer keys in ascending order. Use shortest integer/length encodings. No tags, floats, indefinite items, duplicate keys, nested unknown types, or trailing bytes. Text must be valid UTF-8 without NUL and be bounded in encoded bytes. Byte strings have exact lengths below. Required keys must be present. Unknown keys reject in minor version 0; future negotiated minor versions may define optional extension keys `>=128`. Map size max 16, nested depth max 3. These bounds apply before semantic validation.

| Kind | Key | Type and range | Meaning |
|---|---:|---|---|
| CAPS 02 | 1 | text, 1..32 bytes | Firmware version. |
| | 2 | text, 1..32 bytes | Board ID. |
| | 3 | uint 0..65535 | Minimum minor version. |
| | 4 | uint 0..65535 | Maximum minor version. |
| | 5 | uint 1..3 | Maximum selectable live connections admitted by this firmware run. Source support alone does not raise this value. |
| | 6 | uint 1..8 | Maximum stored bonds. |
| | 7 | uint 0..2^32-1 | Supported report/feature flags. |
| | 8 | uint 1..2^64-1 | Fresh random device session ID. |
| SESSION_OPEN 03 | 1 | text, 1..32 bytes | Host version. |
| | 2 | uint 0..2^64-1 | Host configuration revision. |
| STATUS 12 | 1 | uint 0..6 | State: 0 local, 1 preparing, 2 active, 3 releasing, 4 suspended, 5 pairing, 6 updating. |
| | 2 | uint 0..3 | Selected slot; 0 local. |
| | 3 | array of 0..3 slot maps | Per-slot status, sorted by slot. Minor 2 emits authenticated occupied slots only, bounded by CAPS key 5. |
| | 4 | uint 0..2^32-1 | Error bitset. |
| | 5 | uint 0..2^32-1 | Firmware routing generation. |
| | 6 | pairing map | Required only at negotiated minor 1; forbidden at minor 0. |
| STATUS pairing map | 1 | uint 0..5 | 0 closed, 1 waiting, 2 challenge, 3 rejected, 4 capacity, 5 timeout. |
| | 2 | uint 1..60000 | Remaining milliseconds, required only for waiting/challenge. Host converts to its own monotonic deadline. |
| | 3 | uint 1..2^32-1 | Fresh challenge ID, required only for challenge. |
| | 4 | uint 0..999999 | Numeric comparison value, required only for challenge; display with six digits including leading zeroes. |
| STATUS slot map | 1 | uint 1..3 | Guest slot. |
| | 2 | bytes, exactly 16 | Opaque bond identity token; distinct nonzero tokens identify occupied slots. Legacy single-slot zero tokens are ignored by the host. |
| | 3 | bool | Authenticated encrypted link ready for HID; the host additionally requires key 4 before selection. |
| | 4 | bool | HID subscription state. |
| | 5 | uint 0..65535 | Connection interval in BLE 1.25 ms units; zero when offline. |
| FORGET_BOND 42 | 1 | bytes, exactly 16, nonzero | Opaque identity token; UI confirmation is a host precondition. Firmware accepts only in a verified minor-1 session while local, disarmed, and outside an active pairing window. Missing or failed deletion returns NACK. |
| PAIR_REPLY 43 | 1 | uint 1..2^32-1 | Challenge ID. |
| | 2 | uint 0 | Numeric comparison method only in minor 1. |
| | 3 | bool | Accept or reject the exact current challenge. |

The numeric value and challenge ID appear only in active challenge STATUS, never diagnostics, profile persistence, or logs. A stale, zero, expired, or repeated reply fails closed. STATUS bond tokens are opaque identifiers, never BLE bond keys. Use a new major version for incompatible key or fixed-layout changes.

Minor 2 keeps the minor-one STATUS map unchanged. `BONDS` enumerates retained tokens, including offline peers; the live STATUS slot map is not an inventory. The host accepts a BONDS response only for its outstanding GET_BONDS sequence in the verified session and route generation. Before forgetting a token, it requires a fresh inventory containing it; after the exact FORGET_BOND ACK, it requires another fresh inventory excluding it. A pre-read that proves absence is reported separately as already absent, without issuing a delete. Timeout, NACK, stale response, transport loss, or an unsupported minor never proves absence.

Minor 2 also uses the existing bounded STATUS slot array for up to three simultaneous authenticated connections. Slot numbers are ephemeral channel positions; a host associates profiles through the opaque token on the latest verified STATUS. It rejects duplicate tokens and any slot or selected route beyond CAPS key 5. SWITCH/ARM remain generation-fenced and can target only an admitted READY and subscribed slot. Firmware defaults CAPS key 5 to one until simultaneous three-peer radio, notification, interval and memory tests authorize a higher runtime capacity. The [three-slot canonical STATUS payload](../../tests/vectors/status-three-m2.hex) is an independent fixture; it shows the middle peer authenticated but unsubscribed.
